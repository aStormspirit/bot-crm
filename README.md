# Bot Content CRM

Панель для редактирования **текстов и картинок бота** прямо в GitHub‑репозиториях.
React + Vite, серверные функции Vercel, вход через GitHub OAuth.

## Возможности
- **Проекты и боты.** Слева создаёте проект (например, «Интернет‑магазин») и добавляете в него ботов.
  Каждый бот привязан к репозиторию GitHub, ветке и папкам с текстами и картинками — папки находятся автоматически.
  Список проектов хранится в приватном Gist `bot-crm.json` на вашем GitHub‑аккаунте и доступен с любого устройства.
- Вход через GitHub, список всех своих репозиториев и репозиториев организаций, выбор ветки.
- JSON / YAML — таблица «ключ → текст», поиск, добавление и удаление ключей.
- Сравнение языков бок о бок (`ru.json` ↔ `en.json`): подсветка непереведённых строк и расхождений в переменных `{name}`, `%s`, HTML‑тегах.
- Любые другие текстовые файлы — редактор исходного кода.
- Галерея картинок: загрузка (в том числе drag & drop), замена, переименование, удаление.
- Сохранение одним коммитом: сразу в ветку или в новую ветку с Pull Request. Предупреждение о конфликтах.

## Карта бота (`flow/flow.yaml`)

Если в репозитории бота есть `flow/flow.yaml` (схема рядом — `flow/flow.schema.json`), у бота появляется
вкладка **🗺 Карта**: экраны показаны узлами, стрелки — куда ведут кнопки.

- **Стрелки.** Синяя — кнопка `goto` ведёт на экран. Серая пунктирная — кнопка с `action`, поле `next` у кнопки
  подсказывает, какой экран обычно открывается после действия. Зелёная — `next` у экрана: следующий экран без кнопки.
- **Метки.** `▶ старт` — экран из `start` (/start), `⚡ событие` — экран открывается по `on`, `⚙ код` — экран
  дорисовывает `handler`, `buttons_from` — кнопки взяты с другого экрана, `options` — варианты, кнопки рисует код.
- **Правка.** Нажмите на экран: справа меняются название, текст, картинка (`flow/images`), тип клавиатуры
  (`reply`/`inline`), `next`, кнопки (подпись, цвет, `aliases`, цель `goto` или `url`) и подписи вариантов `options`.
  У кнопок с `action` меняется только подпись и подсказка `next`: само действие задаёт код. `on`, `handler`
  и ключи `options` только для просмотра. «💬 Служебные тексты» — блок `texts`; `{поля}` в них менять нельзя.
- **Карта.** Экраны перетаскиваются, положение сохраняется в `pos`. «⇶ Разложить» расставляет экраны по шагам
  сценария. «＋ Экран» добавляет экран; удалить можно экран, на который никто не ссылается.
- **Проверки** как в `app/flow.py` ботов: схема из репозитория, ссылки `goto`/`next`/`buttons_from`/`start`,
  нет `url` в `reply`-клавиатуре, одно событие — один экран, лимиты подписей (Telegram 64, ВК 40) и текста
  (подпись к картинке в Telegram — 1024). Пока есть ошибки, «Сохранить» недоступна.
- **Сохранение.** Файл меняется через YAML Document: комментарии и порядок ключей остаются, коммит содержит
  только правленые строки. После коммита GitHub Actions бота проверяет файл и перезапускает бота.

У бота с картой нет вкладок «Тексты» и «Картинки»: всё, что бот показывает, правится на карте.

## Рассылки

Вкладка **📣 Рассылки** у бота. Рассылки хранит и отправляет Chat API (`dating-api`, таблица `broadcasts`),
CRM только управляет ими через `/api/chat` — токен Chat API в браузер не попадает.

- **По времени** — одно сообщение всем людям бота сейчас или в указанный момент. Перед отправкой видно, сколько
  получателей. Отправленное отменить нельзя; запланированное и идущую отправку — можно.
- **После события** — каждому человеку через паузу (минуты, часы, дни) после события: впервые написал боту,
  давно не заходил, закончился диалог, закончился премиум. Один раз на человека или после каждого нового события.
  Учитываются события после запуска рассылки, ночью (23:00–10:00 МСК) отправка ждёт утра, кто в поиске
  или в диалоге — получит позже. Рассылку можно поставить на паузу.
- Текст до 4096 символов (с фото в Telegram — до 1024), одно фото, площадки Telegram / ВК / сайт.
- Первой строкой в списке — системная запись **💎 Промо премиума** (если во flow бота есть экраны `partner_left_promo` / `stopped_promo`): только просмотр правила показа и превью двух экранов, без пауз и удаления. Текст, картинка и кнопки правятся на карте (кнопка «🗺 Открыть на карте»), пороги — в Chat API. Карточка берётся из flow, а не из Chat API, поэтому видна и без подключения Chat API. Пороги «5-й, 15-й, 25-й…» и «VK · TG» в карточке заданы текстом в CRM и должны совпадать с Chat API (`services/chat.py`, `PROMO_FIRST` / `PROMO_EVERY`).

## Аналитика

Вкладка **📊 Аналитика** у бота считается по базе Chat API (`GET /api/v1/analytics`), дни — по Москве. Фильтр по площадкам
(Telegram / ВК / сайт) и периоду графиков (14 / 30 / 90 дней).

- **Сводка:** всего пользователей и с премиумом; новые за сегодня, 7 и 30 дней с изменением к прошлому такому же периоду;
  DAU / WAU / MAU и липкость DAU/MAU.
- **Графики по дням:** новые, активные (DAU), диалоги; наведение показывает день и число; есть таблица по дням.
- **Удержание:** retention дня 1, 7 и 30 (доля пришедших, кто вернулся ровно на N-й день) и недельные когорты за 8 недель.
- **Воронка:** написали боту → искали собеседника → был диалог → 3+ диалога → покупали премиум.
- **Диалоги:** за 30 дней, медианная длительность, доля закончившихся жалобой, поисков на человека.
- **Люди** (второй раздел): поиск по ID и имени, фильтры по активности и премиуму, карточка человека — без переписки.

Активность по дням Chat API пишет в `user_activity` с момента выкладки; историю до этого он один раз восстанавливает
по дате прихода, последнему визиту и диалогам — CRM показывает, с какого дня есть журнал.

Переменные Vercel для рассылок и аналитики:

| Переменная | Значение |
|---|---|
| `CHAT_API_URL` | адрес Chat API, например `https://api.chatwithyou.site` |
| `CHAT_API_CRM_TOKEN` | тот же секрет, что `CHAT_API_CRM_TOKEN` у Chat API |
| `CRM_ADMINS` | логины GitHub через запятую: только им открыт раздел. Войти в CRM может любой пользователь GitHub, а рассылка уходит всем людям бота |
| `CF_ACCESS_CLIENT_ID`, `CF_ACCESS_CLIENT_SECRET` | если Chat API закрыт Cloudflare Access (service token) |

## Экраны бота (формат `bot-crm/1`)

Если в репозитории бота есть `content/content.json` (например, `app/content/content.json`), у бота появляется
вкладка **📱 Экраны**: каждое сообщение показано как в Telegram или ВК — картинка, текст, inline-кнопки под
сообщением и нижняя клавиатура. Текст правится прямо в сообщении, кнопка — по клику (подпись, цвет, место
в клавиатуре), картинка — заменой файла. Всё сохраняется одним коммитом.

Код бота читает этот файл при запуске, поэтому всё, что меняется в CRM, отделено от логики.

```jsonc
{
  "format": "bot-crm/1",
  "platform": "telegram",                       // или "vk"
  "texts":   { "GREETING": "Привет!\nНажми /start", "PARTNER_MESSAGE": "👤 Собеседник:\n{text}" },
  "buttons": { "FIND_BTN": "🔍 Найти собеседника" },
  "button_aliases": { "FIND_BTN": ["Найти"] },  // прежние подписи — CRM дописывает при переименовании
  "lists":   { "ROOMS": { "title": "Города", "items": { "msk": "Москва" } } },
  "keyboards": {
    "IDLE_KEYBOARD": { "title": "Главное меню", "type": "reply",          // reply — внизу, inline — под сообщением
      "rows": [[ { "button": "FIND_BTN", "color": "primary" } ], [ { "list": "ROOMS", "item": "msk" } ]] }
  },
  "images":  { "greeting": { "title": "Баннер", "file": "images/greeting.jpg" } },   // путь от content.json
  "screens": [ { "id": "greeting", "title": "Приветствие", "when": "Команда /start",
                 "image": "greeting", "text": "GREETING", "keyboard": "IDLE_KEYBOARD" } ]
}
```

- Цвета: `primary`, `success`, `danger`, `secondary` (или без цвета).
- `{text}`, `{date}`, `{city}` в текстах подставляет бот — CRM не даст их случайно удалить.
- Для ВК подписи кнопок ограничены 40 символами — CRM подсветит превышение.
- `screens` нужен только для превью: какой текст, картинку и клавиатуру бот отправляет вместе.

## Деплой на Vercel

### 1. Создайте GitHub OAuth App
GitHub → **Settings → Developer settings → OAuth Apps → New OAuth App**
(https://github.com/settings/applications/new)

| Поле | Значение |
|---|---|
| Homepage URL | `https://<ваш-проект>.vercel.app` |
| Authorization callback URL | `https://<ваш-проект>.vercel.app/api/auth/callback` |

После создания скопируйте **Client ID** и сгенерируйте **Client secret**.

### 2. Импортируйте проект в Vercel
1. Запушьте эту папку в репозиторий на GitHub.
2. https://vercel.com/new → выберите репозиторий. Framework определится как **Vite** автоматически.
3. В **Environment Variables** добавьте:

| Переменная | Значение |
|---|---|
| `GITHUB_CLIENT_ID` | Client ID из OAuth App |
| `GITHUB_CLIENT_SECRET` | Client secret из OAuth App |
| `SESSION_SECRET` | длинная случайная строка, например результат `openssl rand -hex 32` |
| `APP_URL` | *(необязательно, лучше не задавать)* — если задан, должен точно совпадать с адресом из Callback URL |

4. **Deploy**. Если адрес проекта изменился, обновите callback URL в OAuth App.

### 3. Доступ к репозиториям организаций
Если репозиториев организации нет в списке, владелец организации должен одобрить приложение:
GitHub → Settings → Applications → Authorized OAuth Apps → ваше приложение → **Grant** напротив организации.

## Локальная разработка
```bash
npm install
npm i -g vercel
vercel link            # привязать к проекту на Vercel
vercel env pull .env.local
vercel dev             # http://localhost:3000
```
Для локального запуска создайте отдельный OAuth App с callback `http://localhost:3000/api/auth/callback`.

## Как устроено
```
api/auth/login.js     → редирект на GitHub OAuth (state в cookie)
api/auth/callback.js  → обмен code на токен, зашифрованная httpOnly‑cookie (AES‑256‑GCM)
api/auth/me.js        → текущий пользователь
api/auth/logout.js    → выход
api/github.js         → прокси к api.github.com (только /user и /repos/*, защита от CSRF)
api/chat.js           → прокси к Chat API: /broadcasts, чтение /users и /analytics, только логины из CRM_ADMINS
src/                  → React‑приложение
```
Токен GitHub не попадает в браузер: все запросы идут через `/api/github`.

## Ограничения
- Размер одной картинки — до 3 МБ (лимит тела запроса в функциях Vercel — 4,5 МБ).
- В YAML при правке в табличном режиме вкладки «Тексты» теряются комментарии (карта бота их сохраняет). Чтобы их сохранить, используйте «Исходный код».

## Частые ошибки
**«The redirect_uri is not associated with this application»** — в настройках OAuth App указан не тот Callback URL.
Он должен быть ровно `https://<адрес, где открыта CRM>/api/auth/callback`. Также проверьте, что переменная `APP_URL` в Vercel не задана или совпадает с этим адресом.

**«Сессия входа не найдена»** — CRM открыта не по тому адресу, что указан в Callback URL (например, на preview-деплое). Откройте основной адрес проекта.
